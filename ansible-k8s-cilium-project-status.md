# Ansible + Kubernetes + Cilium/eBPF Project

Project status and roadmap for building a role-based Ansible framework that deploys a kubeadm-based Kubernetes cluster with Cilium (eBPF) networking and Hubble observability.

---

## ✅ Completed

### 1. Ansible Project Structure

A role-based Ansible project (rather than a single monolithic playbook):

```text
ansible-kubernetes/
├── ansible.cfg
├── site.yml
├── inventory/
│   └── hosts.ini
├── group_vars/
│   └── all.yml
└── roles/
    ├── common/
    ├── containerd/
    ├── kubernetes/
    ├── control_plane/
    ├── workers/
    ├── network/
    └── verify/
```

### 2. Inventory

Current cluster:

| Role | Host | IP |
|---|---|---|
| Control plane | `cp1` | `192.168.10.103` |
| Worker | `worker1` | `192.168.10.130` |
| Worker | `worker2` | `192.168.10.61` |

Fixed the initial inventory-group issue by properly structuring:

```text
control_plane
workers
k8s_cluster:children
```

### 3. Common Kubernetes Preparation

Ansible automatically configures nodes with:

- ✅ Required packages
- ✅ Kubernetes sysctl configuration
- ✅ Kernel/network prerequisites
- ✅ Swap-related configuration
- ✅ Basic node preparation

### 4. Container Runtime

Ansible installs and configures **containerd** on all Kubernetes nodes.

### 5. Kubernetes Installation

Ansible installs `kubeadm`, `kubelet`, and `kubectl`, with the version controlled via variables.

- Current Kubernetes version: **v1.34.11**
- Repository configuration switched from the deprecated `apt_repository` to `deb822_repository`

### 6. Kubernetes Control Plane

Ansible automatically performs `kubeadm init` with:

- Kubernetes 1.34.11
- Pod CIDR: `10.244.0.0/16`

...and generates the user's kubeconfig.

### 7. Worker Nodes

Workers automatically join via `kubeadm join`. The join command is generated by the `control_plane` role and retrieved by workers through Ansible variables/`hostvars` — **no hardcoded `worker1`/`worker2` loop**.

### 8. Cilium

Chose **Cilium** over Flannel as the CNI.

- Current version: **Cilium 1.19.5**
- Running on all 3 nodes: `Desired: 3`, `Ready: 3/3`

### 9. eBPF

Cilium provides the Kubernetes networking dataplane using **eBPF**, giving the project a stronger technical foundation than a standard CNI deployment.

### 10. Hubble

Enabled via Ansible.

- `hubble-relay`: `1/1 Running`
- Cilium reports Hubble Relay as healthy

### 11. Verification Role

A `verify` role checks:

- Kubernetes node status
- Cilium status

So a successful run confirms the cluster is actually functioning — not just that Ansible completed.

### 12. Idempotency — Partially Completed

Several tasks are already idempotent, e.g.:

```yaml
when: not kubeadm_initialized.stat.exists
```

```yaml
when: not kubelet_config.stat.exists
```

These prevent `kubeadm init` / `kubeadm join` from re-running unnecessarily.

**Known gap:** the Kubernetes repository signing-key task still reports `changed` due to how the downloaded key is currently handled. This was deliberately left unresolved for now.

> **Idempotency status: 🟡 Mostly done**

The design already supports this — it needs to be **proven**. E.g., adding to inventory:

```ini
[workers]

worker2
worker3
worker4
worker5
```

...should let the playbook automatically configure and join all workers with **no playbook changes**. This is one of the most important original project requirements.

```yaml
kubernetes_version

pod_network_cidr
cilium_hubble_enabled
```

(Already in progress.)

### 4. Improve Error Handling

Introduce a pre-flight validation chain:

Use handlers so services (`containerd`, `sysctl`, `kubelet`) restart **only when configuration actually changes**.
